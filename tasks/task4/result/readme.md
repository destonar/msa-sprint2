# Описание

Добавлен helm chart для сервиса бронирования из задания 2. При этом в values.yaml настраиваются все значения, необходимые для функционирования сервиса (строки подключения и внешние зависимости), а также флаг, включающий и отключающий фичу публикации событий создания бронирований в Kafka. Если флаг выключен, то подключение к Kafka даже не пытается установиться. readinessProbe и livenessProbe обращаются не к /ping (но он тоже есть), а к стандартным для ASP.NET Core healthcheck'ам /health и /alive.

CI/CD пайплайн состоит из следующих этапов:

- build - сборка образа контейнера
- test - запуск контейнера и проверка работоспособности, после чего выключение
- deploy - создание или обновление релиза с помощью helm upgrade
- tag - установка тэга на коммит (а в моем случае просто echo тэга, так как у нас gitlab-ci-local)

Из изменений: так как сервис бронирования обладает gRPC апи, пришлось выделить отдельный порт под http 1.1, чтобы заработал ping и healthcheck, а потому в скриптах проверки работоспособности сервиса я исправил порт на свой собственный.
